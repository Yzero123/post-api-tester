# 腾讯云 SCF 部署步骤（国内直连方案）

Cloudflare 的 `workers.dev` 在国内被墙（DNS 被投毒成 Facebook/Twitter 的 IP，链路也超时），
所以国内用腾讯云 SCF 更稳。

本目录的 `scf_index.py` 就是配套的函数代码，**只用 Python 标准库，不需要 pip 安装任何依赖**。

---

## 为什么用「函数 URL」而不是 API 网关

| | 函数 URL | API 网关触发器 |
| --- | --- | --- |
| 配置步骤 | 开关一个选项 | 建服务 → 建 API → 配后端 → 开响应集成 → 发布 |
| 需要买域名 | 否 | 否（默认域名可用） |
| 需要备案 | 否 | 否 |
| 额外费用 | 无 | 按调用计费（有免费额度） |
| 二进制响应 | 不支持 | 支持（base64） |

我们的场景返回的都是 JSON，**函数 URL 足够**。

---

## 部署步骤

### 1. 创建函数

1. 登录 [腾讯云控制台](https://console.cloud.tencent.com)
2. 顶部搜索「云函数」或「SCF」，进入 **函数服务**
3. 地域选离你近的（例如 **广州** 或 **上海**）
4. 点 **新建** → 选择 **从头开始**

### 2. 填写基本信息

| 配置项 | 填什么 |
| --- | --- |
| 函数名称 | `post-tester-proxy` |
| 运行环境 | **Python 3.10**（或更高） |
| 函数类型 | 事件函数 |

### 3. 贴代码

在「函数代码」区域选 **在线编辑**：

- 把 `scf_index.py` 的全部内容粘进去
- 确认文件名是 **`index.py`**
- 确认执行方法是 **`index.main_handler`**（默认就是）

> 文件名和入口函数必须对上，否则函数跑不起来。

### 4. 高级配置（重要）

| 配置项 | 建议值 | 原因 |
| --- | --- | --- |
| 执行超时时间 | **60 秒** | 必须大于代码里的 `UPSTREAM_TIMEOUT = 30` |
| 内存 | 128 MB | 纯转发，够用 |
| 公网访问 | **开启** | 不开的话函数访问不了 Kling |

> 如果你的函数配置了 VPC，务必额外打开「公网访问」，否则会转发失败。

### 5. 部署并开启函数 URL

1. 点 **部署**
2. 进入函数详情页 → 左侧 **触发管理**（或「访问服务」）
3. 找到 **函数 URL** → 点 **启用**
4. 版本选 `$LATEST` → 确认
5. 复制生成的地址，形如：

```
https://1250000000-abcdefgh.ap-guangzhou.tencentscf.com
```

> 函数 URL 默认是**关闭**的，必须手动开；而且每个版本/别名要单独开。

## 填进工具

打开网页版 → 展开「高级：跨域代理」→ 代理前缀填：

```
https://1250000000-abcdefgh.ap-guangzhou.tencentscf.com/?url=
```

然后正常填目标 URL 和 API Key 发送即可。

---

## 强烈建议：加代理密钥

不加密钥的话，别人拿到你的函数地址就能借你的账号转发流量。

1. 在函数代码里把 `SHARED_SECRET` 改成一段随机字符串：

```python
SHARED_SECRET = "k3j9x2m7q4p8"
```

2. 重新 **部署**
3. 工具里的代理前缀改成：

```
https://1250000000-abcdefgh.ap-guangzhou.tencentscf.com/?k=k3j9x2m7q4p8&url=
```

## 验证是否生效

部署后在工具里发一次请求：

| 现象 | 含义 |
| --- | --- |
| 出现 **401 / 403 等具体状态码和错误正文** | ✅ 代理生效，跨域已绕过 |
| 显示「浏览器没能完成这个请求 / Failed to fetch」 | ❌ 代理没生效，检查地址是否写对、函数 URL 是否启用 |
| 返回 502 + 「转发到目标接口失败」 | 函数访问不了外网，去高级配置开「公网访问」 |
| 返回 403 + 「目标域名不在白名单里」 | 在代码的 `ALLOWED_HOSTS` 里加上该域名后重新部署 |
| 返回 401 + 「代理密钥不正确」 | 代理前缀里的 `k=` 和代码里的 `SHARED_SECRET` 不一致 |

也可以直接用命令行验证（把地址换成你的）：

```bash
curl -i "https://你的函数地址/?url=https%3A%2F%2Fapi-beijing.klingai.com%2Fimage-generation%2Fkling-4.0" \
  -X POST -H "Content-Type: application/json" -d '{"model_name":"kling-v1"}'
```

看到 `access-control-allow-origin` 响应头就说明代理在正常工作。

## 已知限制

1. **函数 URL 不支持二进制响应**。如果目标接口直接返回图片/视频字节流，会被转成 base64 文本。
   我们的场景 Kling 返回的是 JSON（图片以 URL 形式给出），不受影响。
   真要转发二进制，改用 API 网关触发器并勾选「响应集成」。
2. **冷启动**：首次调用可能多 200ms~2s。介意的话可以配 1 个预置并发实例。
3. **超时**：函数超时必须大于 `UPSTREAM_TIMEOUT`，否则会返回函数超时错误。

---

## Kling 的两个额外提醒

1. **请求体格式**：Kling 公开文档的图片生成是
   `{"model_name":"kling-v1","prompt":"...","n":1,"aspect_ratio":"16:9"}`，不是 `contents[]` 结构。
2. **异步任务**：创建任务只返回 `task_id`，需要再发
   `GET /v1/images/generations/{task_id}` 轮询才能拿到图片 URL。
   本代理已支持 GET 转发，但工具界面目前只发 POST，轮询那步要另想办法。
